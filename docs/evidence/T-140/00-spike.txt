# T-140 spike, 2026-11-04: how Run:ai 3.0.20 places each GPU vendor/size choice on the lab cluster (main after T-138).
# Trainings submitted through the Run:ai REST API as the form does (compute + nodePools), one at a time, in team-c.

## Source (Run:ai 3.0.20 frontend)
- Trainings, workspaces, inference, distributed and templates use components/workload-creation/
  hybrid-compute-resource-section: GPU devices / portion / memory typed in the form, node pools in the same section;
  compute presets ("compute resources") only fill those fields when loaded.
- A compute preset has name and description only (no labels); its spec takes extendedResources (amd.com/gpu).
- The form's "GPU devices = N" becomes nvidia.com/gpu: N.

## Conclusions
- A whole AMD GPU must be requested as amd.com/gpu (extended resource); the form's GPU devices field cannot express it.
- AMD fractions by portion work; by memory they need the node's GPU memory label on AMD nodes.
- A workload limited to pool amd that asks for nvidia.com/gpu should be refused with a message, not moved.
